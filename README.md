# NEXO

Сайт и локальный кабинет AI-бота Discord по исходному ТЗ. Рабочее название — NEXO.

## Открыть

Запустите **Start-Nexo.cmd**. Затем откройте http://localhost:3000. Окно сервера должно оставаться открытым.

В текущем окружении зависимости установлены, локальная база создана. Вход в кабинет — регистрация по email и паролю (без подтверждения email). Это не Discord OAuth. Подключение Discord — отдельный шаг, когда настроены ключи приложения.

## Что уже работает

- Русскоязычный адаптивный лендинг, тарифы Basic и Pro ($20/месяц), FAQ и анимированный пример Discord-чата.
- Песочница с настоящими потоковыми ответами LM Studio, остановкой ответа и серверным лимитом 15 сообщений в день на IP (6 запросов/минуту). Сообщения песочницы в базу не записываются.
- Кабинет: обзор, мой бот, песочница, добавление функции, список и отдельные страницы заявок, модерация, характер, оплата, настройки.
- Сохранение настроек в SQLite/D1; история 10 версий prompt; тест нового характера до сохранения; генерация prompt через Qwen.
- Диалог о новой функции через Qwen; структурированная оценка; цена рассчитывается сервером из конфигурации `lib/product.ts`, а не берётся из ответа модели.
- Реальная подготовка ТЗ через Qwen, сохранение документа, скачивание, 5 правок ТЗ, история и уведомления в кабинете. После лимита фиксируется запрос специалисту. Автоматическая отправка специалисту не подключена.
- OAuth-код для Discord: state с одноразовым сроком 10 минут, HttpOnly cookie, зашифрованные токены, список только управляемых серверов, выбор сервера и ссылка установки без Administrator permission. Для живой проверки нужны реквизиты приложения.
- Stripe Checkout для подписки, портал управления, история счетов, проверка HMAC webhook и защита от повторных событий. Кредит Pro обновляется по подтверждённой оплате периода. До настройки Stripe списания невозможны.
- Серверная изоляция записей по владельцу, проверки origin, длины и ролей сообщений, журнал изменений. Сгенерированный документ никогда не исполняется как код.

## Демо на Cloudflare

Сайт выкладывается как Cloudflare Worker (не Pages) с базой D1. Настройки — в **wrangler.cloudflare.json**: имя Worker `nexo`, база `nexo-db`, `DEMO_MODE=true`.

1. Один раз войдите в Cloudflare: `npx wrangler login`.
2. Запустите **Deploy-Cloudflare.cmd** (или `pnpm deploy:cloudflare`).

Скрипт при первом запуске создаёт базу D1 и записывает её ID в wrangler.cloudflare.json, применяет миграции из `drizzle/` (повторно — только новые), собирает сайт (`vinext build --mode cloudflare`) и публикует его. Адрес будет вида `https://nexo.<аккаунт>.workers.dev`.

В демо работают: лендинг, регистрация и вход, кабинет с сохранением настроек, характера и истории prompt. Не работают: AI-ответы (LM Studio есть только локально; на сайте показывается понятное сообщение), Discord OAuth, Stripe, синхронизация с ботом.

Аккаунты: пароль хранится как PBKDF2-SHA256 (100 000 итераций), сессия — случайный токен в HttpOnly cookie на 30 дней, в базе хранится только его хеш. Лимиты: 5 регистраций в час и 10 попыток входа за 10 минут с одного IP. Подтверждение email не сделано: для него нужен почтовый сервис (например Resend) со своим доменом.

## LM Studio

Настройки лежат в **.dev.vars** (локальный файл, исключён из Git). Образец — **.env.example**.

```
LM_BASE_URL=http://localhost:1234/v1
CHAT_MODEL=gemma-4b-instructed
AGENT_MODEL=qwen2.5-coder-3b-instruct
```

Модель агента выбрана по фактическому ответу `/v1/models`. Имя Gemma оставлено по запросу владельца. Если её API Identifier отличается, измените CHAT_MODEL. После изменения настроек перезапустите сайт. В разделе «Настройки» есть проверка сервера и список доступных моделей. Используется OpenAI-совместимый `/v1/chat/completions` со streaming SSE.

Источники: [LM Studio API](https://lmstudio.ai/docs/developer/openai-compat), [Discord OAuth](https://docs.discord.com/developers/topics/oauth2), [Stripe webhooks](https://docs.stripe.com/webhooks).

## Подключить существующего Discord-бота

Нужны Application ID, OAuth Client Secret и TOKEN_ENCRYPTION_KEY (случайный секрет минимум 32 символа). Секреты заполняются локально в .dev.vars, не в чате.

Укажите в Discord Developer Portal redirect URI `http://localhost:3000/api/discord/callback`. Переменные: DISCORD_CLIENT_ID, DISCORD_CLIENT_SECRET, TOKEN_ENCRYPTION_KEY и APP_ORIGIN. Вход запрашивает `identify guilds`.

Для передачи настроек существующему боту предусмотрен контракт:

```
PUT {BOT_API_URL}/guilds/{guildId}/configuration
Authorization: Bearer {BOT_API_KEY}
Content-Type: application/json
```

Тело содержит name, prompt, moderation, categories, sensitivity, alertChannel, customRules, allowedChannels, adminRoles и notifications. API бота обязан повторно проверять guild, разрешения и изоляцию данных. Кнопка «Синхронизировать» показывает успех только после успешного ответа API. Сам Gateway-процесс существующего бота этим сайтом не заменяется.

## Что ещё нужно для полного MVP из ТЗ

1. Загрузить Gemma с нужным API Identifier.
2. Настроить Discord OAuth и связать сайт с API существующего бота. Статистика, активные способности и журнал реальной модерации ждут этого подключения.
3. Выбрать и настроить платёжный сервис. Stripe Price должен быть $20 USD в месяц, а webhook — `/api/payments/webhook`. Проверить подписку, продление, отмену и сбои в test mode до приёма платежей. Возвраты пока выполняются в Stripe Dashboard; отдельного интерфейса возврата нет.
4. Подключить настоящую очередь и изолированный Development/QA Agent: выполнение кода, автоматические тесты, проверки безопасности, staged deploy и rollback. Qwen сейчас готовит ТЗ; наличие ответа модели не означает реализованную функцию. Покупка функций намеренно не запускается до подключения исполнительного агента; применение кредита к покупке ещё не реализовано.
5. Подключить email-провайдер, контакты специалистов и доставку уведомлений в Discord. Настройки уведомлений сохраняются, но внешние сообщения не отправляются.
6. Перед публичным запуском вынести AI backend с localhost на защищённый сервер и организовать публичную авторизацию. Текущая облачная копия — приватное пространство владельца Sites, не публичный многопользовательский SaaS.

Полный MVP из 12 критериев ТЗ пока не завершён без этих внешних подключений. Реализованный локальный сценарий: кабинет → диалог → оценка → ТЗ → правки.

## Разработка и проверки

Стек: React 19, TypeScript, Vinext (Next.js-совместимый App Router), Tailwind, Base UI/Shadcn, SQLite/D1, Cloudflare Workers. Сборка: `pnpm build`; типы: `pnpm exec tsc --noEmit`. Проверки работающего локального сервера: `node scripts/verify.mjs`.

Скрипт проверок использует локальную тестовую сессию Sites, временно меняет имя бота и восстанавливает его. Не запускайте его против production.

WebMCP поддержка опциональна: read_nexo_workspace и save_nexo_personality. В текущем окружении нет поддерживаемого контекста проверки WebMCP; регистрация в браузере не проверена. Визуальное браузерное тестирование и Lighthouse не проводились, оценка 90+ не заявляется.

Применение миграций к новой локальной базе: `pnpm exec wrangler d1 execute DB --local --config wrangler.local.json --file drizzle/0000_elite_stone_men.sql`. Применять один раз; существующую базу не удалять. Новые миграции генерировать через `pnpm db:generate`.

Для новой базы после первой миграции также примените drizzle/0001_luxuriant_marvel_apes.sql и drizzle/0002_accounts.sql той же командой --file. В текущей локальной базе все три миграции уже применены.
